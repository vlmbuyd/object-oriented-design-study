# /wrap {장?} — 하루 닫기 (되짚기 + 기록 + 카드, 한 번에)

읽고 묻고 실습한 하루의 끝에 **딱 한 번** 부른다. 사용자는 어느 폴더에 뭐가 가는지
몰라도 된다. **분배는 전적으로 이 스킬 책임이다.**

장 번호는 생략 가능. 없으면 `state/progress.json` 의 `current_chapter` 를 쓰고,
그것도 없으면 오늘 대화에서 추론한 뒤 **한 번만 확인한다.**

---

## 이 스킬이 지키는 단 하나의 원칙

> **기록의 주인은 사용자다.** 내 설명을 요약해 사용자 자리에 채우지 않는다.

사용자가 자기 언어로 도달한 문장이 중심이고, 내 문장은 `[보충]` 으로 **최대 3개**,
각 두 줄 이내다. 사용자가 끝내 자기 말로 못 옮긴 건 **빈칸으로 남기고 미해결로
내린다.** 빈칸이 내 문장으로 채워지는 것보다 훨씬 낫다. 그게 내일 할 일이다.

---

## 절차

### 0. 아직 안 적힌 대화부터 `scratch/{NN}.md` 로 내린다
오늘 `/ask` 로 오간 것 중 **아직 scratch 에 없는 질답**이 있으면 먼저 append 한다.
날것이 먼저 남아야 그 다음이 있다. 형식은 `/ask` 와 동일:

```
Q. (사용자 질문. 쓴 그대로. 다듬지 않는다)
A. (사용자가 자기 언어로 도달한 문장 그대로)
[보충] (내가 채운 것. 두 줄 이내)
```

사용자 문장을 **한 글자도 고치지 않는다.** 틀린 생각도 그대로 둔다 — 다음 단계의
재료다.

### 1. 오늘 자료를 모은다
- `scratch/{NN}.md` 를 읽는다 (사용자 원본이라 읽어도 된다)
- 오늘 대화 자체
- `dojo/{NN}/` 에 만든 게 있으면 경로만

### 2. 원문 대조 — **book-reader 서브에이전트에 위임**
직접 청크를 열지 않는다. FF 근거가 필요하면 출처 `toss-ff` 로 함께 요청한다.
대조가 필요 없으면 이 단계를 건너뛴다. **불필요한 위임은 하지 않는다.**

### 3. 네 가지로 분류해 대화로 돌려준다
- **내가 스스로 도달한 것** — 칭찬은 짧게. **이게 노트의 주인공이다.**
- **어긋난 것** — 어디가 왜 다른지 + (p.xx)
- **빠진 것** — 핵심인데 못 짚은 것, **최대 2개.** 더 나열하면 장 요약이 된다
- **좋은 질문 하나** — 답 대신 힌트로 돌려준다 (원칙 1)

### 4. 딱 하나 묻는다
> **"오늘 배운 걸 한 문장으로 하면?"**

답을 받은 뒤 5~8을 **한 번에** 처리한다. 다듬지 않고 **그대로** 박는다.
사용자가 건너뛰면 `> 💡` 를 비워둔다.

### 5~8. 저장 (여기서부터는 묻지 않고 끝까지 간다)

| # | 어디에 | 무엇을 |
|---|---|---|
| 5 | `notes/{NN}-{제목}.md` | 되짚기 결과 (없으면 생성, 있으면 병합) |
| 6 | `logs/sessions/{YYYY-MM-DD}.md` | 오늘 질답 (append) |
| 7 | 복습카드 | scratch 의 `### 카드 후보` + 핵심 개념 2~3개 |
| 8 | `state/progress.json`, `logs/events.jsonl` | 진도·미해결·이벤트 |

---

## 5. `notes/{NN}-{제목}.md`

노션에 옮길 거라 **일반 마크다운.** frontmatter·위키링크 금지.
원문 문장을 그대로 옮기지 않는다. 항상 **사용자 문장 + (p.xx)**.

```
# {NN}. {제목}
> 💡 (4번에서 받은 한 문장 그대로)

## 내가 먼저 도달한 것
(노트의 주인공. 사용자 문장을 최대한 살려서)

## 책이 더 밀어준 것
(어긋난 것 + 빠진 것, 페이지 참조)

## 남은 질문
- [ ] ...

## 연결
(관련 개념, 다른 장 번호를 텍스트로 언급)
```

같은 장을 다시 `/wrap` 하면 **덮어쓰지 말고 섹션에 이어 붙인다.**

## 6. `logs/sessions/{YYYY-MM-DD}.md`

```
# {YYYY-MM-DD} / {장}
> 💡 (사용자 답 그대로)

## 질답
Q. (사용자가 쓴 그대로)
A. (사용자 말로 정리한 답)
근거. (책 p.87 / dojo/07/after.tsx 같은 확인 지점만)

## 미해결
- [ ] (답 못 한 질문 그대로)

## 오늘 만든 것
- notes/02-....md
```

`logs/sessions/*.md` 는 사람이 읽는 용도다. **통째로 읽지 않는다.**

## 7. 복습카드

```
python3 scripts/review.py add --chapter {NN} --front "질문" --back "답" --tags 태그
```

- scratch 의 `### 카드 후보` 는 **전부** 등록한다 (사용자가 못 답한 것들이다)
- 거기에 오늘 핵심 개념 **2~3개**를 더한다. 그 이상은 안 된다
- 앞면은 질문형. 답을 외우게 하지 말고 **원리를 떠올리게** 한다
- 등록한 카드는 목록으로 짧게 보여준다

## 8. 상태 갱신

```
python3 scripts/log_event.py --type wrap --chapter {NN} --note notes/{NN}-{제목}.md
```

- `state/progress.json` 의 `chapters[{NN}]` 상태와 `current_chapter` 를 갱신
- 미해결 항목을 `open_questions` 에 넣는다 → 다음 `/pre` 가 여기서 먼저 꺼낸다

## 마무리 출력 (짧게)

무엇이 어디에 갔는지 **표 하나로** 보여주고 끝낸다. 파일 내용을 다시 붙여넣지
않는다. 사용자가 폴더 구조를 몰라도 되게 만드는 게 이 스킬의 목적이다.

```
notes/02-객체지향-프로그래밍.md   되짚기
logs/sessions/2026-07-30.md      오늘 질답 4개
복습카드 3장                      (2일 뒤 due)
```

## 하지 말 것

- 사용자 답을 내 문장으로 고쳐서 `A.` 에 적기 — **가장 흔한 실패다**
- `[보충]` 4개 이상, 두 줄 초과
- 장 요약을 새로 써주기. 이건 되짚기지 요약이 아니다
- 4번 질문 전에 파일부터 쓰기
- 어디에 저장할지 사용자에게 되묻기. **분배는 이 스킬이 판단한다**
